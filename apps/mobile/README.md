# @ftm/mobile — Follow the Money, on a phone

An Expo (React Native) client for the same data the web build shows: publicly
disclosed campaign contributions and legislative activity, placed side by side.

It is **completely offline**. The data bundle is compiled into the app, so there
is no API, no server, no key, no account, and no network request of any kind at
runtime. It behaves identically in airplane mode. See the header comment in
[`index.ts`](./index.ts) for the full list of what this app does not do.

## Run it

```bash
cd apps/mobile
npm install        # this app installs its own dependencies — see "Why not a workspace?"
npx expo start     # then press i / a, or scan the QR code with Expo Go
```

No API keys, no `.env`, no configuration. Nothing to sign in to.

Other useful commands, all from `apps/mobile`:

```bash
npx expo start --web              # run it in a browser
npx tsc --noEmit                  # typecheck (also checks packages/core)
npx expo export --platform web    # static web build in ./dist
npx expo export --platform ios    # Hermes bundle, proves the native build works
```

## Screens

| Route | What it shows |
| --- | --- |
| `/` | Overview: headline counts, global search, largest overlaps, coverage notes, the long disclaimer |
| `/bills` | Every bill, filterable by sector, chamber and free text; sortable |
| `/bills/[id]` | One bill: sector tags with confidences, and every member whose donor sectors overlap it |
| `/reps` | Every member, filterable by chamber, state and free text |
| `/reps/[bioguideId]` | One member: donor-sector breakdown, coverage gaps, their overlapping bills |
| `/about` | The framing in full, the overlap formula, the bands, and what this app does on your device |

Search is a plain in-memory filter over the bundled `search.json`. Nothing you
type is sent, logged, or stored.

Screenshots of every screen, light and dark, are in
[`docs/screenshots/`](../../docs/screenshots) (`mobile-*.png`). They were taken
from the web export at a 390×844 viewport; the framing banner is visible in all
of them.

## Refreshing the bundled data

The JSON in `assets/data/` is generated by the ingest pipeline, not edited by
hand. From the **repository root**:

```bash
npm run export     # rewrites apps/web/public/data AND apps/mobile/assets/data
```

or, for a full re-fetch and re-classify first:

```bash
npm run pipeline
```

Then rebuild the app (`npx expo start --clear`, or re-run `expo export`) so the
new JSON is compiled in. The files are `.gitignore`d — everyone regenerates
their own.

`assets/data/` currently holds the seven top-level export files: `index.json`,
`industries.json`, `legislators.json`, `bills.json`, `overlaps.json`,
`search.json`, `awards.json`.

### One known gap

The exporter also writes per-entity detail files — `bill/<id>.json` and
`member/<id>.json` — but only into `apps/web/public/data`. They are not part of
the mobile bundle, so this app reconstructs its detail screens from the
top-level files. Two things are therefore missing or partial here:

- a bill's plain-English summary and per-sector rationale (bill detail shows the
  sector tags and confidences, and links to the bill text on Congress.gov);
- a member's complete donor breakdown (member detail shows the exporter's
  top-three sectors unioned with every sector appearing in that member's overlap
  rows).

Both gaps are stated on screen as coverage notes rather than hidden. If the
mobile client should have parity, the fix is in
`packages/ingest/src/export.ts`: write the per-entity files into `MOBILE_DATA_DIR`
as well as `WEB_DATA_DIR`, and add a bundler-friendly index of them (Metro
cannot `require()` a dynamic path, so a generated manifest module would be
needed).

## Framing rules this app is bound by

These are not stylistic preferences. They are the point of the project.

1. **Every disclaimer string comes from `@ftm/core`** (`packages/core/src/disclaimer.ts`).
   No screen writes its own wording. See `src/components/Framing.tsx`.
2. **The framing banner is rendered by the root layout**, outside the navigator,
   so no screen can omit it and there is no dismiss control.
3. **An overlap score is only ever rendered through `<OverlapScore/>`**, which
   always renders the band label alongside the number and never a bare figure.
4. **No partisan colour, ever.** Party is a neutral letter; it never colours,
   sorts, or ranks anything.
5. **No red/green on scores.** Magnitude uses one neutral ink ramp — see
   `ramp` in `src/theme.ts`.

Light and dark tokens mirror `apps/web/src/styles.css` value for value.

## Why not an npm workspace?

`apps/mobile` is deliberately **not** listed in the root `package.json`
`workspaces` array, and installs its own `node_modules`.

Adding it was tested: `npm install` still exits 0, but it re-resolves the shared
root tree (hundreds of packages relocated, dozens of versions changed) because
React Native's dependency set is large and pins transitive versions that the web
app also uses. React Native plus npm workspace hoisting is fragile in exactly
this way, and a mobile build breaking the existing web install is a bad trade for
a `node_modules` folder.

The cost is one extra `npm install` in `apps/mobile`. Nothing else in the repo
changes.

## How `@ftm/core` is wired in

There is no `node_modules/@ftm/core` here to resolve, so `metro.config.js` does
three things (each is commented in the file):

1. adds `packages/core` to `watchFolders` — keeping the project root in the list,
   since Metro crawls exactly `watchFolders` and nothing else;
2. a `resolveRequest` hook that maps `@ftm/core` to the package's TypeScript
   **source** (`packages/core/src/index.ts`) rather than its built `dist/`, so the
   app never depends on `npm run build:core` having been run — and rewrites
   `packages/core`'s NodeNext-style `./x.js` specifiers to `./x.ts`, which Metro
   does not do by itself;
3. sets `experiments.onDemandFilesystem: false` in `app.json`. Expo's on-demand
   filesystem discards `watchFolders` during `expo export` and reads everything
   else through a fallback that is scoped to the project root, which makes any
   package living above the project root fail with
   `Failed to get the SHA-1 for: packages/core/src/index.ts`.

`tsconfig.json` mirrors the same mapping with `paths`, so `tsc --noEmit`
typechecks `packages/core` alongside the app.

The disclaimer strings are never copied. There is exactly one copy of them in
this repository, in `packages/core/src/disclaimer.ts`.
